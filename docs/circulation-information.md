# Circulation de l'information du projet

## Objectif

La circulation de l'information permet à chaque membre de l'équipe de savoir où trouver les informations du projet et comment signaler un problème.

## Circuit de l'information

1. Un besoin ou un problème est identifié.
2. Une Issue GitHub est créée pour le signaler.
3. La personne concernée crée une branche dédiée.
4. Les modifications sont réalisées sur cette branche.
5. Les modifications sont enregistrées avec un commit.
6. La branche est envoyée sur GitHub.
7. Une Pull Request est créée vers `main`.
8. Un autre membre de l'équipe relit la modification.
9. Les éventuelles corrections sont réalisées.
10. La Pull Request est fusionnée dans `main`.

## Où trouver l'information ?

| Information | Emplacement |
|---|---|
| Problème ou besoin | Issue GitHub |
| Travail en cours | Branche Git |
| Modification proposée | Pull Request |
| Échanges sur une modification | Pull Request |
| Documentation du projet | Dossier `docs/` |
| Version validée | Branche `main` |

## Règles de communication

- Utiliser les Issues pour signaler un problème ou un besoin.
- Utiliser les Pull Requests pour proposer une modification.
- Décrire clairement le contexte, les changements et l'impact.
- Répondre aux commentaires de revue dans la Pull Request.
- Conserver une trace des décisions importantes dans la documentation.
